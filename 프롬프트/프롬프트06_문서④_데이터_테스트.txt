- 04_데이터정의서.md — Supabase 표 세 개의 테이블 정의서(한글 이름 · 칸 이름 · 자료형 · 필수 · 키 · 정해진 값 · 설명) + 표끼리 어떻게 이어지나(키) + 사진 저장소 receipts(비공개, 파일 이름 규칙) + 표 · 저장소마다 "누가 읽고 쓰나"(공개용 키 = 화면 / 커넥터 = 정산 담당이 시킨 Claude) + 어느 기능(F · A · M 번호)이 읽거나 넣나 + public\config.js의 항목 두 개 + 폴더별 공개 범위(public = 인터넷 공개 / 개발문서 · output\sql = GitHub 비공개 저장소까지 / input · 읽은결과.xlsx = 내 PC만)
- 05_테스트목록.md — 테스트마다 T-번호 · 확인하는 기능(F · A · M 번호) · 하는 방법 · 기대 결과 · 통과 칸(비워 둬).
  T-01 표 3개가 만들어지고 직원 8명이 들어갔나 (영수증 · 품목은 0줄)
  T-02 사진 저장소 receipts가 비공개인가
  T-03 보안 점검에서 우리가 만든 표 · 저장소에 대한 경고가 0개인가
  T-04 첫 화면 — 등록 탭에 제출자 8명, 목록은 "비어 있음", 집계 0원, 맨 아래 v1.0
  T-05 웹 등록 — receipt_21로 1건 등록하면 목록에 1건(등록 방식 웹), 저장소에 사진 1개. 구분을 택시로 고르면 목적 · 인원 · 접대 상대가 잠긴다
  T-06 AI 읽기 — 읽은결과.xlsx의 영수증 건수 · 품목 줄 수 · 합계, "품목 합 = 합계"인 건수, "카드 끝 4자리 = 제출자 카드"인 건수를 세어 정답과 대조
  T-07 샘플 3장(receipt_03 · 10 · 17)의 일시 · 가게 · 합계가 사진과 같은가
  T-08 커넥터로 넣은 뒤 등록 방식이 AI인 영수증의 건수 · 품목 줄 수 · 합계가 읽은결과.xlsx와 같은가
  T-09 같은 등록을 한 번 더 해도 늘어나지 않나
  T-10 화면 목록 21건 · 시크릿 창에서도 21건 · 상세에서 사진이 열리고 등록 방식 AI인 줄은 "품목 합 = 합계"
  T-11 화면 집계와 Claude가 커넥터로 계산한 답이 같은가 (전체 합계 · 목적별 합계 · 식사 1인당)
  T-12 말로 고치기 — receipt_15의 인원을 3에서 4로 고치면 화면의 식사 1인당이 바뀌나
  T-13 공개용 키 권한 목록 — employee 읽기 · receipt 읽기와 넣기 · receipt_item 읽기 · 저장소 올리기와 보기만 있고, 고치기 · 지우기는 없는가
  T-14 화면 상태와 폰 폭 — 불러오는 중 · 비어 있음 · 정상이 보이고, 창을 좁혀도 등록 칸이 한 줄씩 보이나 (오류 상태는 시안에서 확인)
  T-15 git 저장 — 저장 이력에 v1.0, 저장된 파일에 public\index.html · public\config.js가 있고 input 폴더와 읽은결과.xlsx는 없는가
