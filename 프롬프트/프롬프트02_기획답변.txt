네가 한 기획 관련 질문과 추천 방향에 대해 아래 내용을 최우선으로 적용해서 진행해. 만약 내가 작성한 내용과 네가 추천한 기획 방향이 서로 충돌하는 부분이 있다면 나에게 따로 알려줘. 네 질문 중 내가 답변하지 않은 항목은 네가 제안한 추천 방식대로 진행하고, 질문에 없었더라도 아래에 내가 추가로 작성한 사항이 있다면 기획에 빠짐없이 반영해.

A. 사용자와 실행
- 직원 8명: 로그인 없이 화면을 연다(로그인은 이번에 붙이지 않는다 — 그래서 오늘은 가상 데이터만 넣는다). 자기 영수증을 등록하고, 모두의 목록과 집계를 본다.
- 정산 담당(나): 화면으로 전체 목록과 집계를 본다. 웹앱을 만드는 사람도 나다 — 만들고 확인하는 일(표 만들기 · 확인용 데이터 넣기 · 조회 · 수정)은 Claude + Supabase 커넥터로 한다.
- 화면은 HTML 파일 하나(public\index.html)에 탭 세 개. 설정은 public\config.js. 인터넷에 공개되는 폴더는 public 하나뿐이고, 그 안에는 이 두 파일만 둔다. 문서 · SQL · input · output은 public에 넣지 않는다.
- 내 PC에서 확인할 때는 run.bat을 더블클릭한다 — Python 기본 기능으로 public 폴더만 http://127.0.0.1:8001 로 열고 크롬이 켜진다. 내 PC(127.0.0.1)에서만 연다. 설치할 것은 없어야 해.
- 배포 뒤에는 Vercel이 준 주소(https://….vercel.app)로 연다. 내 PC가 꺼져 있어도 열려야 한다.

B. 영수증의 칸
- 사진에 있는 칸: 구분(가게 종류를 보고 식사 · 카페 · 택시 중 하나) · 일시(결제 일시, 영수증에 찍힌 그대로) · 가게 이름(택시는 운수회사 이름) · 품목(이름 · 수량 · 단가 · 금액) · 합계(원) · 카드 끝 4자리 — 확인용 데이터는 네가 사진에서 읽는다
- 사진에 없는 칸: 제출자 · 목적(일반 · 회식 · 접대) · 인원 · 접대 상대(목적이 접대일 때만) · 메모 — 확인용 데이터는 제출목록에서 가져온다
- 화면 등록에서는 직원이 구분 · 일시 · 가게 · 합계와 사진에 없는 칸을 직접 넣는다.
- 택시는 목적 · 인원 · 접대 상대를 비운다. 품목이 없으니 품목 1줄 "택시 운임"(수량 1, 단가 = 합계)으로 넣는다.
- 카드번호는 끝 4자리만. 사진에서 읽기 어려운 칸은 지어내지 말고 비워 두고 알린다.

C. 데이터가 들어가는 두 길
- ① 화면 등록(직원): 제출자 · 사진 1장(필수) · 구분 · 일시 · 가게 · 합계 · 목적 · 인원 · 접대 상대 · 메모. 품목과 카드 끝 4자리는 넣지 않는다. 사진은 저장소에 올리고, 파일 이름은 화면이 영문 · 숫자로 새로 짓는다(web_날짜_시각_임의4자리). 등록 방식 = 웹.
- ② 확인용 데이터(나 + Claude): 사진 20장을 Claude가 읽고, 제출목록과 사진 파일 이름으로 맞춰 output\읽은결과.xlsx 를 만든다 → 내가 확인한다 → 커넥터로 표에 넣는다. 등록 방식 = AI. 사진 20장은 내가 대시보드 저장소에 직접 올린다(커넥터에는 파일 올리기가 없다).
- 같은 사진 파일 이름은 두 번 넣지 않는다.

D. 화면 — 탭 세 개 + 상세
- S-01 등록 / S-02 목록(최근 순, 월 · 제출자 · 구분 고르기, 줄마다 등록 방식 표시) / S-03 집계(월을 고르면 건수 · 합계, 구분별 · 목적별 · 직원별 합계, 식사 1인당 금액) / S-04 상세(목록에서 줄을 누르면 사진 · 칸 · 품목 표, 그리고 "품목 합 = 합계" 표시. 웹 등록분은 "품목 없음")
- 화면 상태 네 가지: 불러오는 중 · 정상 · 비어 있음 · 오류(이유를 문장으로)
- 등록 화면의 일시는 날짜(달력에서 고르기)와 시각(24시간 형식으로 직접 입력, 예 12:20) 두 칸으로 받는다.
- 화면 맨 아래에 작은 글씨로 버전(v1.0)을 표시한다 — 배포된 화면이 어느 버전인지 눈으로 보려고.
- 꾸미지 말고 단순하게. 폰 폭에서도 등록 칸이 한 줄씩 보이게.
- 고치기 · 지우기 버튼은 만들지 않는다.

E. 집계 규칙
- 월 = 일시의 연-월. 처음엔 가장 최근 월을 보여 준다.
- 목적별 합계에서 택시는 "목적 없음"으로 따로.
- 식사 1인당 = 그 달 식사 영수증 합계 ÷ 식사 영수증 인원 합계, 원 단위 반올림.

F. Supabase
- 표 세 개, 칸 이름은 영어 소문자.
  employee(직원): emp_no 사번(키) · name · dept · title  (법인카드 끝 4자리는 표에 넣지 않는다 — 직원.xlsx에만 둔다)
  receipt(영수증): id(자동) · photo_path 사진 파일 이름(겹치지 않음) · emp_no(직원과 잇는다) · kind 구분 · used_at 일시 · store_name 가게 · total 합계 · card_last4 · purpose 목적 · people 인원 · guest_company 접대 상대 · memo · source 등록 방식(AI · 웹) · created_at 등록 시각(자동)
  receipt_item(품목): id(자동) · receipt_id(영수증과 잇는다) · item_name · qty · unit_price · amount
- 자동 번호(id)는 identity 방식(generated always as identity)으로 만든다 — 화면에서 등록할 때 번호 권한 오류가 나지 않게.
- 일시는 시간대 없는 형식으로 영수증 시각 그대로 저장한다.
- 사진 저장소 receipts — 비공개. 화면에서는 볼 때만 10분짜리 임시 주소로 연다.
- 공개용 키(화면)에 주는 권한: employee 읽기 · receipt 읽기와 넣기(등록 방식이 웹인 줄만) · receipt_item 읽기 · 저장소 receipts 올리기와 보기. 고치기 · 지우기는 없다. 모든 표에 권한 규칙(RLS)을 켠다. 새 프로젝트라 표를 만들어도 공개용 키에 자동으로 열리지 않으니 권한(grant)을 직접 준다.
- 비밀 키와 DB 비밀번호는 쓰지 않는다. public\config.js에는 주소와 공개용 키만, 개발 단계에서 커넥터로 채운다. 공개용 키는 공개되는 파일에 들어가도 된다 — 할 수 있는 일은 권한 규칙이 정한다.

G. 확인
- 확인용 데이터: 사진 20장 → 영수증 20건. 품목 줄 수와 합계는 네가 읽은 결과로 보고해 줘. 정답 숫자는 내가 따로 가지고 대조할 거야.
- 영수증마다 "품목 합 = 합계", "카드 끝 4자리 = 제출자 카드"를 확인하는 칸을 만든다.
- 웹 등록 1건까지 더하면 21건.
- 화면 집계와 Claude가 커넥터로 계산한 답이 같아야 해.
- 배포 주소에서도 내 PC와 같은 숫자가 나와야 해. run.bat 창을 닫아도 배포 주소는 열려야 해. 배포 주소 뒤에 /CLAUDE.md 를 붙여도 열리면 안 돼.

H. 저장 · 배포
- git: 브랜치는 main 하나. 저장하지 않을 것(.gitignore)은 input 폴더 전체와 output\읽은결과.xlsx. 첫 저장은 v1.0(태그), 저장 이름 "v1.0 경비 정산 웹앱 첫 완성".
- GitHub: 비공개 저장소 adv5-receipt. 가입과 저장소 만들기는 내가 한다. 올리기(push)는 내가 말할 때만 하고, 올리기 전에 올라갈 파일 목록과 비밀 키 검사 결과를 먼저 보여 준다.
- Vercel: 가입 · 가져오기 · 배포는 내가 Vercel 화면에서 한다. 빌드 없이 public 폴더를 그대로 내보낸다. 환경 변수는 쓰지 않는다 — 설정은 config.js 하나.
- 고치기: 배포 뒤 요구사항이 바뀌면 문서 고치기 → 내 PC에서 고치기 → run.bat으로 확인 → 저장(v1.1) → 올리기 → 자동 배포 순서로 간다.
