좋아, 그 내용으로 확정.
먼저 개발문서 폴더에 01_요구사항정의서.md 를 확정본으로 저장해 줘. 요구사항마다 R-01 … 번호, [입력] [처리] [출력] [확인] + [지켜야 할 것] 구조, 사용자 두 종류(직원 · 정산 담당)와 ③ 웹앱으로 판단한 이유, 그리고 배포에 관한 요구사항(인터넷에 공개되는 것은 public 폴더뿐 · 설정은 config.js · git 저장과 올리기 · 배포 주소에서의 확인 · 로그인은 이번에 없으므로 가상 데이터만)을 넣어 줘.
이어서 02_화면설계.md 를 써 줘. 다섯 가지가 들어가야 해. 개발 용어 없이 업무 말로.
1. 화면 목록 — S-01 등록 · S-02 목록 · S-03 집계 · S-04 상세. 확인용 데이터 넣기와 묻기 · 고치기는 화면이 아니라 Claude와 대화로 한다는 것, 그리고 직원은 배포 주소로 열고 나는 내 PC에서 확인할 때 run.bat으로 연다는 것도 적어 줘
2. 화면 그림 — 글자와 선으로 그린 배치도. 화면마다 위에서 아래로 무엇이 놓이는지(맨 아래 버전 표시까지)
3. 사용 흐름 — 직원(등록 → 목록에서 내 영수증 확인 → 상세)과 정산 담당(목록 → 상세 → 집계에서 월 고르기), 번호로
4. 화면 상태 네 가지 — 불러오는 중 · 정상 · 비어 있음 · 오류 — 상태마다 무엇이 보이고 무엇이 잠기는지 표로
5. 폰에서 보이는 모습 — 폭이 좁을 때 등록 칸과 목록이 어떻게 바뀌나
각 항목이 어느 요구사항(R-번호)에서 왔는지 괄호로 적어 줘. 다 쓰면 화면 그림과 상태 표만 보여 줘.
