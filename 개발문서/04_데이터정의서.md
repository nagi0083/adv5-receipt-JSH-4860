## 1. 테이블 정의서

### 1.2 receipt (영수증)

| 한글 이름 | 칸 이름 | 자료형 | 필수 | 키 | 정해진 값 | 설명 |
|---|---|---|---|---|---|---|
| 번호 | id | bigint | O(자동) | 기본키 | 1부터 자동(identity) | 화면 · 사람이 넣지 않는다 |

| 카드 끝 4자리 | card_last4 | text | | | 숫자 4자리 | AI 등록만 채운다. 웹 등록은 빈칸 |
| 목적 | purpose | text | | | 일반 · 회식 · 접대 | 택시는 빈칸 |
| 인원 | people | integer | | | 1 이상 | 택시는 빈칸 |

| 메모 | memo | text | | | | |

표가 스스로 막는 규칙
- 구분이 택시면 목적 · 인원 · 접대 상대는 모두 빈칸이어야 한다.
- 접대 상대가 있으면 목적은 접대여야 한다.
- 같은 사진 파일 이름은 두 번 들어갈 수 없다. (R-13)
- 화면(공개용 키)으로 넣을 때는 추가로: 등록 방식 = 웹, 사진 이름이 `web_`로 시작, 구분 · 일시 · 가게 이름 · 합계 필수. 카드 끝 4자리 · 번호 · 등록 시각은 넣을 수 없다. (R-11)

## 2. 표끼리 이어지는 방법

```
employee (직원)                receipt (영수증)                  receipt_item (품목)
┌──────────────┐  1 : 여러 개  ┌────────────────────┐  1 : 여러 개  ┌──────────────────┐
│ emp_no (키)  │──────────────<│ emp_no             │               │                  │
│ name         │               │ id (키)            │──────────────<│ receipt_id       │
│ dept · title │               │ photo_path ─ ─ ─ ─ ┼ ─ ┐           │ item_name · qty  │
└──────────────┘               └────────────────────┘   │           │ unit_price · amt │
                                                        │           └──────────────────┘
                                 저장소 receipts         │
                                 ┌────────────────────┐ │
                                 │ 사진 파일 (이름) ◄ ─ ┼ ┘  (이름으로 이어짐, 키는 아님)
                                 └────────────────────┘
```

- 직원 한 명 → 영수증 여러 장 (receipt.emp_no → employee.emp_no)
- 영수증 한 장 → 품목 여러 줄 (receipt_item.receipt_id → receipt.id)
- 영수증 한 장 → 사진 한 장 (receipt.photo_path = 저장소의 파일 이름)
- 이어진 직원 · 영수증은 지울 수 없다(지우기는 하지 않는다).

## 3. 사진 저장소 receipts

| 항목 | 값 |
|---|---|
| 공개 여부 | **비공개**. 주소만으로는 열리지 않고, 화면이 볼 때마다 10분짜리 임시 주소를 받는다(F-08) |
| 파일 종류 · 크기 | jpg · png · webp, 한 장 10MB까지 |
| 이름 규칙 — AI 등록(확인용 데이터) | 원래 이름 그대로 `receipt_01.jpg` ~ `receipt_20.jpg`. 정산 담당이 대시보드에서 올린다(M-01) |
| 이름 규칙 — 웹 등록 | 화면이 새로 짓는다 `web_YYYYMMDD_HHMMSS_xxxx.확장자` (날짜 · 시각은 등록을 누른 때, xxxx는 영소문자 · 숫자 4자리, 확장자는 jpg · jpeg · png · webp 소문자). 이 형식이 아니면 화면은 올릴 수 없다(F-04) |
| 폴더 | 쓰지 않는다(저장소 맨 위에 바로 둔다) |
| 덮어쓰기 · 지우기 | 하지 않는다 |

## 4. 누가 읽고 쓰나

- **공개용 키 = 화면**: 직원 · 정산 담당이 브라우저에서 쓰는 화면. 권한 규칙(RLS)이 정한 일만 할 수 있다.
- **커넥터 = 정산 담당이 시킨 Claude**: 모든 일을 할 수 있지만, 바꾸는 일은 SQL을 먼저 보여 주고 승인받는다. 지우기 · 비우기 · 표 지우기는 하지 않는다.
- **대시보드 = 정산 담당**: Supabase 화면에서 직접.

| 대상 | 공개용 키(화면) | 커넥터(Claude) | 대시보드(정산 담당) |
|---|---|---|---|
| employee | 읽기 — F-02, F-06, F-07 | 넣기 — A-02(완료) · 읽기 — A-06, A-10 | 보기 — M-03 |
| receipt | 읽기 — F-06, F-07, F-08 · 넣기(웹만) — F-05 | 넣기(AI) — A-05(완료) · 읽기 — A-06, A-10 · 고치기 — A-07(승인 뒤) | 보기 — M-03 |
| receipt_item | 읽기 — F-08 | 넣기 — A-05(완료) · 읽기 — A-06 · 고치기 — A-07(승인 뒤) | 보기 — M-03 |
| 저장소 receipts | 올리기(`web_…`만) — F-04 · 보기(임시 주소) — F-08 | 파일 목록 읽기 — A-05, A-10 (올리기 기능 없음) | 올리기 — M-01(완료) · 보기 — M-03 |
| 표 · 권한 · 저장소 만들기 | 없음 | A-01(완료) | 보기 — M-03 |

공개용 키에 **없는** 권한: 고치기 · 지우기(모든 표 · 저장소), 품목 넣기, 직원 넣기, 등록 방식 "AI" 줄 넣기, 카드 끝 4자리 넣기.
